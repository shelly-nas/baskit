# FR-005: Route Optimization

## Overview

Route Optimization is a Premium-tier feature that generates an optimal multi-store or single-store shopping plan for the items on a user's active list. Given the user's current location, it evaluates two strategies — cheapest (minimise total grocery spend, accepting multiple store visits) and fastest (minimise total travel + shopping time, typically one store) — and presents both so the user can choose. The chosen route is then handed off to an external navigation app. Free users see a tasteful upsell prompt when they attempt to access the route optimizer.

## 1. Route Strategy Selection

### 1.1 Requirements

- **FR-005.1.1**: The system SHALL provide two route strategies: `cheapest` and `fastest`
- **FR-005.1.2**: The `cheapest` strategy SHALL assign each list item to the store that offers the lowest current price for that item, then plan a multi-store route that visits only the stores required by at least one item assignment
- **FR-005.1.3**: The `fastest` strategy SHALL identify the single store that stocks the greatest number of list items at a competitive overall price, minimising travel and in-store time
- **FR-005.1.4**: The system SHALL allow the user to select their preferred strategy (cheapest or fastest) before generating a route
- **FR-005.1.5**: The system SHALL remember the user's last-used strategy and pre-select it on subsequent route requests
- **FR-005.1.6**: The system SHALL allow the user to switch strategies without re-entering their location
- **FR-005.1.7**: The system SHALL gate route optimization behind Premium subscription; a request from a Free-tier user SHALL return HTTP 402 with body `{"error": "route_optimization_premium_required", "upgrade_url": "/subscription/upgrade"}`

### 1.2 Strategy Selection Flow

1. Premium user opens a list that has at least one catalogue-matched item with current price data
2. User taps "Optimize route"
3. Flutter client requests the user's device location (latitude, longitude) via the device location API
4. Flutter client presents the strategy selector: two cards ("Cheapest" and "Fastest") with a brief description each
5. Flutter client pre-selects the strategy from the user's stored preference
6. User confirms strategy and taps "Generate route"
7. Flutter client sends POST to route-service with `list_id`, `latitude`, `longitude`, `strategy`

### 1.3 Freemium Upsell Flow (Free User)

1. Free user taps "Optimize route"
2. Flutter client receives HTTP 402 from route-service
3. Flutter client displays an upsell bottom sheet: "Route optimization is a Baskit Premium feature. Upgrade for €4.99/month to get personalized shopping routes that save you time and money." with a "Upgrade to Premium" CTA and a "Not now" dismiss button
4. User taps "Not now" → bottom sheet closes; user remains on the list screen

### 1.4 Error Handling

- Device location permission denied → "Baskit needs your location to plan a route. Please enable location access in your device settings"
- Location accuracy below 500 metres → "Unable to determine your location accurately. Please try again or enter your location manually"
- Free user → HTTP 402 with upsell payload
- List has no catalogue-matched items with price data → "No price data is available for your list items. Add products from the catalogue and try again"
- route-service unavailable → "Route optimization is temporarily unavailable. Please try again"

## 2. Route Calculation

### 2.1 Requirements

- **FR-005.2.1**: The system SHALL complete route calculation within 5 seconds (95th percentile) for lists of up to 50 items across the 6 supported supermarket chains
- **FR-005.2.2**: The system SHALL consider only stores within a radius of 20 kilometres of the user's location
- **FR-005.2.3**: The system SHALL use real driving or cycling travel times, obtained from the Google Maps Distance Matrix API (primary) or HERE Maps (fallback), when calculating the fastest route
- **FR-005.2.4**: The system SHALL fall back to straight-line distance (Haversine formula) when both external mapping APIs are unavailable, and SHALL include a disclaimer in the response: `"travel_times_estimated": true`
- **FR-005.2.5**: The system SHALL calculate the estimated total in-store shopping time as 3 minutes per item assigned to a store
- **FR-005.2.6**: The system SHALL calculate the total estimated time for a route as the sum of travel times between each waypoint plus in-store shopping time at each store
- **FR-005.2.7**: The system SHALL calculate the `cheapest` strategy item assignment using a greedy lowest-price allocation per item, then apply Nearest Neighbour heuristic to order the required store visits starting from the user's location
- **FR-005.2.8**: The system SHALL include in the route response for each store waypoint: `store_id`, `store_name`, `store_chain`, `address`, `latitude`, `longitude`, `items_to_buy` (array of items assigned to this store), `subtotal_cents`, `estimated_travel_minutes_from_previous`, `estimated_shopping_minutes`
- **FR-005.2.9**: The system SHALL include in the top-level route response: `strategy`, `total_cost_cents`, `total_travel_minutes`, `total_shopping_minutes`, `total_time_minutes`, `potential_savings_cents` (difference between this route's total cost and the most expensive single-store option), `travel_times_estimated` (boolean)
- **FR-005.2.10**: The system SHALL include items that have no price data in a separate `unpriced_items` array in the response; these items SHALL NOT affect cost calculations or store assignments
- **FR-005.2.11**: The system SHALL cache route responses in Redis with a TTL of 15 minutes; cache key includes `list_id`, `strategy`, and the user's location rounded to 3 decimal degrees

### 2.2 Route Calculation Flow

1. route-service receives POST with `list_id`, `latitude`, `longitude`, `strategy`
2. route-service validates Premium subscription
3. route-service fetches all catalogue-matched items and their current prices from price-service
4. route-service identifies all stores within 20 km of the user's location from store-service
5. For `cheapest`: route-service assigns each item to its cheapest store within radius; builds store visit set; applies Nearest Neighbour to order visits
6. For `fastest`: route-service finds the store with the best item coverage and competitive aggregate price; plans a single-store visit
7. route-service requests travel times between waypoints from Google Maps Distance Matrix API
8. route-service assembles route response, calculates totals, and writes to Redis cache
9. route-service returns route response to Flutter client
10. Flutter client renders the route plan screen

### 2.3 Error Handling

- Google Maps API quota exceeded → route-service retries with HERE Maps; if both fail, uses Haversine and sets `travel_times_estimated = true`
- All stores are outside 20 km radius → "No supported stores are within 20 km of your location. Broaden your location or check back later"
- All list items are unpriced → "No price data is available for your list items. Add products from the catalogue and try again"

## 3. Route Plan Display

### 3.1 Requirements

- **FR-005.3.1**: The system SHALL display the route plan as an ordered list of store waypoints, each showing: store name, chain logo, address, items assigned, subtotal in euros, estimated travel time from the previous stop, and estimated in-store time
- **FR-005.3.2**: The system SHALL display both the `cheapest` and `fastest` route summaries side-by-side on the strategy comparison screen so the user can compare total cost and total time before committing
- **FR-005.3.3**: The system SHALL display a `potential_savings_cents` badge on the `cheapest` route expressed in euros and cents (e.g., "Save €3.47 vs most expensive option")
- **FR-005.3.4**: The system SHALL display a disclaimer when `travel_times_estimated = true`: "Travel times are estimates based on distance. Actual times may vary"
- **FR-005.3.5**: The system SHALL allow the user to manually swap an item's assigned store by selecting an alternative store from the available options for that item; the route totals SHALL recalculate immediately on the client using the cached price data without a new API call
- **FR-005.3.6**: The system SHALL allow the user to exclude a store from the route; all items assigned to the excluded store SHALL move to the `unpriced_items` list with a note: "Store excluded from route"

### 3.2 Route Plan Display Flow

1. route-service returns route response
2. Flutter client renders the strategy comparison screen showing cheapest vs fastest summaries
3. User selects a strategy (or keeps the pre-selected one)
4. Flutter client renders the ordered waypoint list for the selected strategy
5. User reviews assigned items at each store and optionally swaps items or excludes stores
6. User taps "Start shopping" to proceed to navigation

## 4. Navigation Integration

### 4.1 Requirements

- **FR-005.4.1**: The system SHALL allow the user to launch turn-by-turn navigation to the first store waypoint in a selected route by opening an external navigation app
- **FR-005.4.2**: The system SHALL support the following navigation apps in order of preference: Google Maps, Apple Maps (iOS only), Waze
- **FR-005.4.3**: The system SHALL detect which navigation apps are installed on the device and present only installed options to the user
- **FR-005.4.4**: The system SHALL open the external navigation app with the destination pre-filled as the first store's address when the user taps "Navigate to [store name]"
- **FR-005.4.5**: The system SHALL allow the user to navigate to any individual waypoint in the route, not only the first one, by tapping "Navigate" on that waypoint card
- **FR-005.4.6**: The system SHALL construct the navigation deep link using the store's `latitude` and `longitude`, not only the address string, to ensure accuracy

### 4.2 Navigation Launch Flow

1. User taps "Navigate to [store name]" on a waypoint card
2. Flutter client checks which supported navigation apps are installed using `url_launcher` package
3. If multiple apps are available, Flutter client presents a bottom sheet: "Open with: [Google Maps] [Apple Maps] [Waze]"
4. User selects an app
5. Flutter client opens the selected app's deep link with the store coordinates as the destination
6. The external app takes over navigation; Baskit remains in the background

### 4.3 Error Handling

- No supported navigation app installed → "No navigation app found. Please install Google Maps or Waze to get directions"
- Navigation app fails to open → "Unable to open [app name]. Please open it manually and search for [store name] [address]"

## 5. Manual Store Selection & Route Modification

### 5.1 Requirements

- **FR-005.5.1**: The system SHALL allow the user to override the computed route by manually selecting a specific store from the list of stores within 20 km for any list item
- **FR-005.5.2**: The system SHALL allow the user to lock an item to a specific store so that re-running the optimizer respects the lock and does not reassign the item
- **FR-005.5.3**: The system SHALL allow the user to unlock a previously locked item assignment
- **FR-005.5.4**: The system SHALL recalculate route totals (cost and time) immediately when the user manually overrides a store assignment; the recalculation SHALL use locally cached price data and SHALL complete within 500ms

### 5.2 Error Handling

- User locks item to a store with no current price data for that item → "No current price is available for [item] at [store]. The item will appear in your list but will not be included in cost calculations"

## 6. API Endpoints

### 6.1 Route Optimization Endpoints

All endpoints require a valid JWT Bearer token. Premium-gated endpoints return HTTP 402 for Free users.

```
POST /api/v1/routes/optimize
GET  /api/v1/routes/:routeId
```

### 6.2 Request / Response Shape

POST `/api/v1/routes/optimize` request body:
```json
{
  "list_id": "uuid",
  "latitude": 52.3702,
  "longitude": 4.8952,
  "strategy": "cheapest" | "fastest"
}
```

POST `/api/v1/routes/optimize` response body (abbreviated):
```json
{
  "route_id": "uuid",
  "strategy": "cheapest",
  "total_cost_cents": 3247,
  "total_travel_minutes": 22,
  "total_shopping_minutes": 15,
  "total_time_minutes": 37,
  "potential_savings_cents": 347,
  "travel_times_estimated": false,
  "waypoints": [...],
  "unpriced_items": [...]
}
```

## 7. Database Schema

### 7.1 Routes Table

```sql
routes (
  id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  list_id                 UUID NOT NULL REFERENCES lists(id),
  user_id                 UUID NOT NULL REFERENCES users(id),
  strategy                VARCHAR(10) NOT NULL CHECK (strategy IN ('cheapest', 'fastest')),
  total_cost_cents        INTEGER NOT NULL CHECK (total_cost_cents >= 0),
  total_travel_minutes    INTEGER NOT NULL CHECK (total_travel_minutes >= 0),
  total_shopping_minutes  INTEGER NOT NULL CHECK (total_shopping_minutes >= 0),
  potential_savings_cents INTEGER NOT NULL DEFAULT 0,
  travel_times_estimated  BOOLEAN NOT NULL DEFAULT FALSE,
  origin_latitude         NUMERIC(9,6) NOT NULL,
  origin_longitude        NUMERIC(9,6) NOT NULL,
  created_at              TIMESTAMP NOT NULL DEFAULT NOW()
)
```

### 7.2 Route Waypoints Table

```sql
route_waypoints (
  id                              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  route_id                        UUID NOT NULL REFERENCES routes(id) ON DELETE CASCADE,
  store_id                        UUID NOT NULL REFERENCES stores(id),
  visit_order                     INTEGER NOT NULL CHECK (visit_order >= 1),
  subtotal_cents                  INTEGER NOT NULL DEFAULT 0,
  estimated_travel_minutes        INTEGER NOT NULL DEFAULT 0,
  estimated_shopping_minutes      INTEGER NOT NULL DEFAULT 0
)
```

### 7.3 Route Waypoint Items Table

```sql
route_waypoint_items (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  waypoint_id     UUID NOT NULL REFERENCES route_waypoints(id) ON DELETE CASCADE,
  list_item_id    UUID NOT NULL REFERENCES list_items(id),
  price_cents     INTEGER NOT NULL CHECK (price_cents >= 0),
  is_locked       BOOLEAN NOT NULL DEFAULT FALSE
)
```

### 7.4 Related Tables

- `lists` / `list_items`: source list for route optimization (owned by FR-003)
- `stores`: store locations and metadata (owned by FR-004)
- `prices`: current price data for item assignment (owned by FR-004)
- `users`: subscription tier check (owned by FR-001)

## 8. Security Considerations

### 8.1 Threat Mitigation

- **Premium gate bypass**: Subscription tier is validated server-side from the JWT claims and cross-checked against the `users` table; client-side Premium flags are not trusted
- **Location spoofing**: The route-service does not act on user-provided location for any security-sensitive decision; location is used only for store radius filtering and route ordering, where spoofing carries no meaningful impact
- **External API key exposure**: Google Maps and HERE Maps API keys are stored as environment variables in the route-service `.env` file and are never returned to the client
- **Route access control**: A route record is only returned to the user who created it; `user_id` is validated on every GET `/api/v1/routes/:routeId` request

## 9. Testing Requirements

### 9.1 Unit Tests

- Greedy cheapest item assignment: each item assigned to the store with the lowest `price_cents`
- Nearest Neighbour store ordering: waypoints ordered correctly from origin
- Haversine fallback: straight-line distances computed correctly for known coordinate pairs
- In-store time estimate: 3 minutes × item count per store
- Total time calculation: sum of travel times and shopping times across all waypoints

### 9.2 Integration Tests

- POST `/api/v1/routes/optimize` with strategy `cheapest` returns waypoints sorted by Nearest Neighbour order
- POST `/api/v1/routes/optimize` with strategy `fastest` returns a single store waypoint
- POST `/api/v1/routes/optimize` with all unpriced items returns a response with empty `waypoints` and all items in `unpriced_items`
- POST `/api/v1/routes/optimize` from a Free-tier user returns HTTP 402
- GET `/api/v1/routes/:routeId` from a different user returns HTTP 403
- Route response sets `travel_times_estimated = true` when mapping APIs are unavailable
- Redis cache returns the same route within TTL without hitting the mapping API again

### 9.3 Security Tests

- Confirm Free-tier JWT receives HTTP 402 on route optimization endpoint
- Confirm a user cannot retrieve another user's route by guessing a route UUID
- Confirm API keys are not present in any API response body or response headers

## 10. Performance Requirements

- **FR-005.10.1**: Route calculation (including external mapping API call) SHALL complete within 5000ms (95th percentile) for a 50-item list across 6 stores
- **FR-005.10.2**: Route calculation from Redis cache SHALL complete within 300ms (95th percentile)
- **FR-005.10.3**: Client-side route total recalculation on manual store override SHALL complete within 500ms
- **FR-005.10.4**: Navigation app deep link SHALL open the external app within 2 seconds of the user's tap

## 11. Dependencies

- Backend Services: route-service (port 3006), price-service (port 3004), store-service (port 3005)
- Database: PostgreSQL (routes, route_waypoints, route_waypoint_items tables)
- Cache: Redis (route cache, TTL 15 minutes)
- External: Google Maps Distance Matrix API (primary travel times)
- External: HERE Maps API (fallback travel times)
- Flutter packages: `url_launcher` (navigation deep links), `geolocator` (device location)
- Auth: user-service (JWT validation, subscription tier)

## 12. Acceptance Criteria

- [ ] A Premium user with a populated list can tap "Optimize route" and receive a route plan within 5 seconds
- [ ] Both cheapest and fastest strategy summaries are shown side-by-side so the user can compare cost and time
- [ ] The cheapest strategy assigns each item to its lowest-priced store and orders store visits from the user's location
- [ ] The fastest strategy returns a single store covering the most items
- [ ] A savings badge ("Save €X.XX vs most expensive option") is shown on the cheapest route
- [ ] A Free user tapping "Optimize route" sees the upsell bottom sheet and no price or route data
- [ ] When device location permission is denied, the user receives a clear error message with guidance to enable it
- [ ] Items without price data appear in the `unpriced_items` section and are excluded from cost calculations
- [ ] The user can tap "Navigate to [store]" and the external navigation app opens with the correct coordinates pre-filled
- [ ] When no navigation app is installed, the user sees an error message listing supported apps
- [ ] The user can manually lock an item to a specific store and the optimizer respects this on re-run
- [ ] When both mapping APIs are unavailable, straight-line distance is used and the disclaimer is shown
